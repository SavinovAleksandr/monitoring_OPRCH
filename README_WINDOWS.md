# ОПРЧ: исправление Windows Excel (подготовленный патч)

В этом пакете нет изменённого готового `.xlsm`: его необходимо собрать **в самом Excel для Windows**. Исходный `Шаблон_мониторинг_ОПРЧ.xlsm` из `main` не следует считать исправленным после одного только обновления `.bas`.

## Быстрый запуск одним файлом

Если вы скачали **архив-установщик** из ChatGPT, **не нужно предварительно клонировать репозиторий**. Распакуйте архив, запустите из PowerShell:

```powershell
powershell -NoProfile -File .\install_monitoring_OPRCH_windows.ps1
```

Первый запуск требует подключения к GitHub: скрипт автоматически скачивает исходники из зафиксированного коммита `a3c663d099de9a6b51efc1c888ffc8e87679048b`, помещает патч рядом с ними, собирает новую книгу средствами Excel Windows и выполняет проверку. По завершении все исходники и готовый XLSM сохраняются локально. **Непосредственно в скачанном архиве VBA-модулей и готовой исправленной книги пока нет.**

Если исходники уже скачаны, можно использовать `-SourceZip <путь>` или `-ExistingRepo <путь>` без загрузки по сети. Вручную переносить четыре патч-файла нужно только при выполнении старого способа из раздела ниже.

## Почему не запускалось

1. **Обнаруженный дефект компиляции VBA**: `OPRCH_Sheets.bas`, процедура `WriteSummaryRow`, содержит 26 последовательных символов продолжения строки (` _`). VBA допускает максимум 24. Ошибка компиляции может блокировать запуск любых макросов книги.
2. **Скрытые ошибки**: `InitOPRCHUISilent` оставляет глобальный флаг `gOPRCHQuiet = True`; ошибки `AnalyzeOPRCH` затем не показываются. Патч восстанавливает предыдущий флаг, записывает ошибку в `Log` и возвращает прежний режим расчёта Excel.
3. **Непереносимый Python-сборщик**: абсолютный путь `/Users/asavinov/...` и `/tmp` не подходят для Windows.
4. **Неопределённость готового `.xlsm`**: внедрение `vbaProject.bin` через стороннюю библиотеку не эквивалентно проверке компиляции и реальному запуску в Excel для Windows. Для теста Windows используйте сборку через Excel COM.

## Установка

Нужен установленный **настольный Microsoft Excel для Windows**. Python не требуется: PowerShell сам применяет патч и готовит модули Windows-1251. При желании для независимой проверки можно использовать Python 3.10+.

1. Скачайте или клонируйте [SavinovAleksandr/monitoring_OPRCH](https://github.com/SavinovAleksandr/monitoring_OPRCH). Распакуйте **все четыре файла из этого архива** в корень репозитория, рядом с `OPRCH_*.bas` и шаблоном.
2. В Excel: **Файл → Параметры → Центр управления безопасностью → Параметры центра → Параметры макросов → Доверять доступ к объектной модели проектов VBA**. Этот доступ требуется только для программного импорта; после установки его можно отключить. **Не включайте все макросы глобально.**
3. Закройте все открытые экземпляры исходного шаблона. Из PowerShell, находясь в каталоге репозитория, выполните: `powershell -NoProfile -File .\make_windows_workbook.ps1`.
4. Скрипт сохраняет резервные копии изменённых исходников в `.oprch_windows_backup_*`, исправляет UTF-8 `.bas`, заново формирует шесть настоящих файлов `*_win1251.bas`, проверяет ограничения VBA и импортирует их через штатный механизм Excel.
5. Создаётся **новый** файл `Шаблон_мониторинг_ОПРЧ_Windows.xlsm` (уже существующий файл не перезаписывается). Скрипт создаёт кнопки, запускает анализ демо-данных и проверяет, что в `Summary` появились результаты, а в `Log` нет `ERROR`.
6. Откройте новую книгу, проверьте **Alt+F11 → Debug → Compile VBAProject**, затем выполните `Alt+F8 → AnalyzeOPRCH` на фактических данных. Исходную книгу не удаляйте, пока результаты не проверены.

Для независимого статического теста можно запустить `python apply_windows_fixes.py --repo . --check` после выполнения PowerShell. Если нужно **только исправить исходники без Excel**, используйте `python apply_windows_fixes.py --repo .` на любой ОС.
Если исполнение `.ps1` запрещено корпоративной политикой, обратитесь к системному администратору или установите шесть исправленных `*_win1251.bas` через `Alt+F11 → File → Import File`. **Не отключайте политики безопасности обходными командами.**

## Что проверено и что нет

- **Проверено статически:** структура патча, совпадение исходных фрагментов с репозиторием, отсутствие продолжений строк сверх 24 после преобразования (контроль `--check`), байтовая кодировка Windows-1251 и размер модулей.
- **Проверяется при запуске PowerShell на Windows:** импорт в VBE, создание новой книги, запуск `AnalyzeOPRCH`, наличие сводки и отсутствие ошибок в журнале.
- **Не проверено здесь:** выполнение в установленном на вашей Windows Excel и корректность инженерных расчётов ОПРЧ по реальным аварийным данным. Успешный smoke test не заменяет сравнение с ручным расчётом по методике.

## Состав

- `apply_windows_fixes.py` — необязательный кроссплатформенный вариант исправления исходников и статических проверок (Python).
- `make_windows_workbook.ps1` — исправление исходников без Python, штатный импорт в Excel для Windows и проверочный прогон.
- `windows_patch_manifest.json` — точные замены исходного кода, проверяемые до применения.
- `README_WINDOWS.md` — эта инструкция.

**Важно:** GitHub API возвращал `403 Resource not accessible by integration` при попытке создания ветки/записи. Пакет можно применить к локальному клону, после чего отправить коммит в GitHub при наличии прав записи.

## Как отправить исправления в GitHub при наличии прав записи

После успешного локального прогона создайте ветку, например `fix/windows-vba-compile-and-install`, и выполните:

```powershell
git add OPRCH_*.bas build_oprch_1_8.py apply_windows_fixes.py make_windows_workbook.ps1 windows_patch_manifest.json README_WINDOWS.md
git commit -m "Fix VBA compilation and Windows Excel macro installation"
git push -u origin fix/windows-vba-compile-and-install
```

Рекомендовано создать pull request в `main` и проверить в Excel на рабочей машине перед слиянием. Не добавляйте в коммит каталог `.oprch_windows_backup_*` или созданную тестовую книгу с данными.
