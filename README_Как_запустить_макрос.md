# Инструкция: мониторинг участия в ОПРЧ

Версия макроса: **1.8.4**

Универсальный шаблон: **любая станция / любое событие** через листы `RawData` и `Config`. Вкладки «Запрос» нет.

Норматив: **Приложение 14** (оценка участия при событиях) и **Приложение 1** (ступени динамики при испытаниях) к Техтребованиям, ред. 01.03.2026.

---

## 0. Коротко: что вводить и что считается

### Исходные данные (обязательно)

| Что | Куда | Требование |
|-----|------|------------|
| Время, частота, мощности генераторов | лист `RawData` | шаг ≤ 5 с; колонка `Время` |
| Окно архива | `RawData` | по п. 3.1 желательно ≥ 5 мин до отклонения и до возврата в 50±0.1 Гц > 5 мин |
| Список генераторов и нормативы | лист `Config` | станция, имя, заголовки колонок P/f, тип, Pном, S, fнч, РМ (1/0), компоновка |
| Режим расчёта | `Config` X13 | `Авария` или `Испытание` |
| Глобальные уставки | `Config` W/X | fном, автопоиск, строгий дефицит (W17) и др. |

Пустые t5/t10/fнч заполняет кнопка **Применить пресеты типов**.

### Один запуск = всё сразу

**Отдельно «только количественно» / «только качественно» запускать не нужно.**  
`AnalyzeOPRCH` в одном проходе считает:

1. **Количественно (Прил. 14 §4.2)** — P0, f0, Pтреб(t), tр, дефицит по периодам, реакция 15 с, сумма неблока.  
2. **Качественно (Прил. 14 §4.4)** — тип реакции 1–8.  
3. **Ступени динамики t5/t10 (Прил. 1)** — всегда при `Кач_вкл=1`, но влияние на вердикт зависит от режима (ниже).

Макрос сам отсекает неприменимое по п. 4.1.2 / 4.1.3 (только в режиме «Авария»).

### Режимы (`Config` X13)

| Режим | Когда | Что жёстко | t5/t10 |
|-------|-------|------------|--------|
| **Авария** | реальные события в сети | без РМ: S=6 %, fнч=0.15; дефицит «хотя бы в одном периоде» → **НАРУШЕНИЕ** | только замечание |
| **Испытание** | контрольные испытания | S/fнч из Config; применимость 4.1.x не отсекает | несдача → **НАРУШЕНИЕ** |

Главный столбец результата — `Summary!Вывод`. Для неблочной ТЭС норматив — **сумма станции** (п. 4.2.10).

## 1. Как запустить (готовая книга с макросами)

### Рекомендуемый способ

1. Откройте **`Шаблон_мониторинг_ОПРЧ.xlsm`** (макросы уже внутри).  
2. Разрешите макросы — при открытии появятся кнопки на `Config`.  
3. Проверьте/обновите `RawData` и `Config` под текущее событие.  
4. Нажмите **Запустить мониторинг ОПРЧ** (или `Alt+F8` / `Option+F8` → `AnalyzeOPRCH`).  
5. Если кнопок нет: `Alt+F8` → **`InitOPRCHUI`**.

**Не** запускайте `SetupOPRCHTemplate` на заполненной книге — сотрёт данные.  
Вкладки «Запрос» нет: коды запросов к ОИК храните вне книги.

### Запасной импорт (если xlsm недоступен)

Файлы `*_win1251.bas` — Windows-1251 (для русской Windows). Шесть модулей (лимит VBA ~64 КБ).  
См. `КАК_ИМПОРТИРОВАТЬ_VBA.txt` / `OPRCH_Install_win1251.bas`.

### Демо в шаблоне

В `RawData`/`Config` по умолчанию лежит пример одной аварии (неблочная ТЭС) — только чтобы сразу проверить запуск. Для работы по другим станциям и событиям замените данные и строки Config.

## 2. Формат входных данных (`RawData`)

### Обязательные столбцы
- `Время` — дата/время Excel.
- Частота — один из вариантов:
  - общий столбец `Частота`,
  - или отдельные столбцы, например `f Блок 1`, `f Блок 2`, `f СЛПК`.
- Мощность каждого генератора — отдельный столбец (например `ТГ-5`, `Р Блок 1`, `P ТГ-3Э`).

### Правила
- Заголовки — только в строке 1.
- Данные в анализируемом интервале идут без разрывов по времени.
- Имена столбцов мощности/частоты должны точно совпадать с тем, что указано в `Config`.
- Рекомендуемый шаг данных — не более 5 с (в противном случае в `Log` появится предупреждение `WARN Разрыв по времени ...`).

## 3. Параметры в `Config`

### 3.1 Таблица генераторов (со строки 2, колонки A..V)

| Кол. | Поле | Пояснение |
|------|------|-----------|
| A | Станция | |
| B | Генератор | |
| C | Колонка_мощности | точное имя столбца из `RawData` |
| D | Колонка_частоты | точное имя столбца из `RawData` |
| E | Тип_оборудования | `ПТУ_неблок`, `ПТУ_блок`, `ГТУ`, `ПГУ_утил`, `ПГУ_сбросн`, `ГПА` |
| F | Pном, МВт | |
| G | S, % | |
| H | fнч, Гц | |
| I | Вкл (1/0) | участвует ли генератор в расчёте |
| J | Кач_вкл (1/0) | включать ли качественную проверку |
| K | t5, c | нормативное время первой ступени |
| L | dP5, %Pном | первая ступень по мощности |
| M | t10, c | нормативное время второй ступени |
| N | dP10, %Pном | вторая ступень по мощности |
| O | Уст_допуск, %Pном | допуск установившегося отклонения |
| P | В сумму станции (1/0) | включать в суммарный мониторинг станции |
| Q | Контр_уст (1/0) | контролировать ли установившееся значение |
| R | Паропровод | тег общего паропровода (например `Э`, `У`) |
| S | Pmax, МВт | максимальная эксплуатационная мощность (по умолчанию `Pном`) |
| T | Pmin, МВт | технический минимум (по умолчанию `0`) |
| U | РМ (1/0) | есть ли регулятор мощности (пусто = 1). В режиме **Авария** при `0` принимаются S = 6 % и fнч = 0.15 Гц независимо от колонок G/H (п. 4.2.9 МУ). В режиме **Испытание** всегда берутся фактические S/fнч |
| V | Компоновка | `блок` или `неблок` (пусто = по типу оборудования). П. 4.2.10 (оценка по сумме, индивидуальная — только при нарушении) применяется к **неблочной** части |

**Pmax / Pmin.** Если в `Config` заданы `S` и `T`, макрос:
- вычисляет располагаемый резерв `Резерв '+' = max(0, Pmax − P0)` и `Резерв '-' = max(0, P0 − Pmin)`;
- ограничивает `Pтреб` резервом в нужную сторону (капинг): если исходный `Pтреб` больше резерва, принимается значение резерва;
- в `Summary` количественный статус становится `Ограничен Pmax` / `Ограничен Pmin` (вместо `Нарушение`), в колонке `Pтреб исх., МВт` сохраняется неограниченное значение, в колонке `Ограничение` — тип лимита;
- при резерве в требуемую сторону `< 5 % Pном` в `Log` записывается `WARN` и событие помечается как возможное ограничение диапазоном;
- на графике `<Ст>_<Ген>_Граф` добавляются красные пунктирные уровни `ΔPmax` и `ΔPmin` (относительно `P0`).

Если `S` и `T` пусты — Pmax принимается равным `Pном`, Pmin = 0 (полный диапазон, капинг фактически отключён).

**Пресеты типов.** Если ячейки `L..P` или `H` (fнч) оставлены пустыми/нулевыми, при запуске они заменяются на значения по умолчанию в зависимости от `E Тип_оборудования` — см. таблицу ниже (колонку `t10` можно быстро заполнить для всех строк кнопкой **Применить пресеты типов**):

| Тип | t10, c | t5 | dP5 | dP10 | Уст_допуск | fнч | Источник |
|-----|-------:|---:|----:|-----:|-----------:|----:|----------|
| ПТУ_блок (газомазутный) | 300 | 15 | 5 | 10 | 1 | 0.075 | табл. Е.1 Прил. 1 (5 % за 15 с, 10 % за 5 мин) |
| ПТУ_блок_уголь (пылеугольный) | 360 | 15 | 5 | 10 | 1 | 0.075 | табл. Е.1 Прил. 1 (10 % за 6 мин) |
| ПТУ_неблок (общий паропровод) | 420 | 15 | 5 | 10 | 1 | 0.075 | табл. Е.2 Прил. 1 (10 % за 7 мин по сумме ТГ) |
| ГТУ        | 120 | 15 | 2.5 | 10 | 1 | 0.075 | табл. Е.3 Прил. 1 (2.5 % за 15 с, 5 % за 30 с, 10 % за 2 мин) |
| ПГУ_утил   | 120 | 15 | 2.5 | 10 | 1 | 0.075 | табл. Е.4 Прил. 1 |
| ПГУ_сбросн | 300 | 15 | 5 | 10 | 1 | 0.075 | табл. Е.5 Прил. 1 (как ПСУ) |
| ГПА        | 60 | 15 | 5 | 10 | 1 | 0.075 | табл. Е.6 Прил. 1 (10 % за 1 мин) |

Пресеты срабатывают только для пустых ячеек — любые заданные значения сохраняются. Для типа оборудования, содержащего в названии `уголь`/`пылеуг`, применяется `t10 = 360 с`.

| W15/X15 | Макс. число событий (1 = только первое) | 3 |
| W16/X16 | Ограничение Pтреб, %Pном (0 = нет) | 10 |

> Глобальные настройки — только в `W/X`. Книги до 1.3.x (настройки в `T/U`) больше не читаются: колонки `U/V` заняты признаками «РМ» и «Компоновка». Запустите `SetupOPRCHTemplate` или перенесите настройки вручную.

- **Pre-start буфер** — сколько секунд добавить в график **до** расчётной точки старта. На расчёт не влияет, только на ширину окна графика.
- **Интервал графика** — длительность окна графика **после** расчётной точки старта.
- **Окно установившегося** — на какое окно (последние N секунд качественного интервала) усредняется установившееся значение мощности.
- **Порог реакции 15 с** — минимальное изменение мощности в нужную сторону (в % Pном) через 15 с после выхода частоты за `fнч`, при котором реакция регулятора частоты вращения считается имеющейся (п. 4.2.11 МУ требует лишь *наличия* реакции, поэтому порог небольшой — он отсекает шум телеизмерения).
- **Усреднение P0/Pтек** — окно усреднения значений мощности перед расчётной точкой старта и перед точкой количественной оценки (п. 4.2.6 МУ). `0` — используются текущие значения (допустимо при стабильных сигналах).
- **Режим** — `Авария` (мониторинг реальных отклонений частоты) или `Испытание` (контрольные испытания). В «Аварии» для строк с `РМ=0` принудительно S = 6 %, fнч = 0.15 Гц; применимость по п. 4.1.2/4.1.3 проверяется. В «Испытании» всегда фактические S/fнч, применимость не отсекает оценку.
- **Макс. окно события / число событий** — автопоиск всех выходов частоты за `fнч`; короткие выбросы < 5 с отбрасываются.
- **Ограничение Pтреб** — `|Pтреб|` не больше указанной доли Pном (Приложение: 10 %).

### 3.3 Профили `Kд(t)` (колонки `AA:AI`)

Таблица профилей (со строки 3):
- `AA` — `Тип_оборудования` (например `ПТУ_блок`, `ПТУ_неблок`, `ГТУ`, `ПГУ_утил`, `ПГУ_сбросн`, `ГПА`);
- `AB/AC` — точка `(t0, Kд0)`;
- `AD/AE` — точка `(t1, Kд1)`;
- `AF/AG` — точка `(t2, Kд2)`;
- `AH/AI` — точка `(t3, Kд3)`.

Как используется:
- `Kд(t)` считается кусочно-линейно по заданным точкам времени; минимум 2 точки должны быть заполнены, остальные можно оставить пустыми;
- профиль `AB:AI` обязателен: если для типа оборудования нет строки профиля, расчёт завершается с ошибкой;
- столбец фиксированного `Kд` в таблице генераторов удалён; источник `Kд(t)` — только профиль `AB:AI`;
- профиль применяется и в количественном расчете (`Pтреб`), и в расчете `Pтреб_ср` для установившегося режима.

Шаблон по умолчанию соответствует алгоритму критерия «Отсутствие адекватной/должной реакции» из Приложения к МУ (карта параметров: ТЭС — 15 с / 300 с газомазутные, 360 с пылеугольные, 420 с общий паропровод; ПГУ — 15 с / 30 с / 120 с):

| Тип | (t0, Kд0) | (t1, Kд1) | (t2, Kд2) | (t3, Kд3) |
|-----|-----------|-----------|-----------|-----------|
| ПТУ_блок | 0 с, 0.50 | 15 с, 0.50 | 300 с, 1.00 | 600 с, 1.00 |
| ПТУ_блок_уголь | 0 с, 0.50 | 15 с, 0.50 | 360 с, 1.00 | 600 с, 1.00 |
| ПТУ_неблок | 0 с, 0.50 | 15 с, 0.50 | 420 с, 1.00 | 600 с, 1.00 |
| ГТУ, ПГУ_утил | 0 с, 0.25 | 15 с, 0.25 | 30 с, 0.50 | 120 с, 1.00 |
| ПГУ_сбросн | 0 с, 0.50 | 15 с, 0.50 | 300 с, 1.00 | 600 с, 1.00 |
| ГПА | 0 с, 0.50 | 15 с, 0.50 | 60 с, 1.00 | 600 с, 1.00 |

То есть для ТЭС `Kд = 0.5` на участке 0…15 с (половина статической первичной мощности должна быть выдана к 15-й секунде), затем линейный рост до `1.0` к моменту окончания времени регулирования. Фактические `Kд(15 с)` и `Kд(колич. интервал)` по каждому профилю выводятся в `Log` при запуске. Короткие имена `ПТУ` / `ПСУ` / `ГТУ` автоматически сопоставляются с профилем (`ПТУ` → `ПТУ_блок`).

### 3.4 Выбор рядов графиков (колонки `AJ:AL`)

- `AJ` — имя ряда;
- `AK` — показывать ряд на относительном графике (`1/0`);
- `AL` — показывать ряд на абсолютном графике (`1/0`).

В шаблоне создаются чекбоксы, привязанные к `AK:AL`, поэтому можно включать/выключать ряды перед запуском без редактирования кода.

## 4. Алгоритм макроса

Для каждого включённого генератора (`J=1`):

1. **Поиск событий** (выходов частоты за `fнч`, п. 3.1 МУ):
   - авто: все интервалы вне `fнч` длительностью ≥ 5 с, не более `X15` штук; короткие выбросы отбрасываются;
   - вручную (`X4=0`): одно событие вокруг ближайшей точки к `X3`;
   - для каждого события строится отдельная строка `Summary` и листы с суффиксом `_E2`, `_E3`…

1a. **Применимость** (только режим `Авария`):
   - количественная (п. 4.1.2): `|Δf| ≥ 0.2 Гц` не менее 30 с (ТЭС) / 60 с (ГПА);
   - качественная (п. 4.1.3 / 4.4.3 / 4.4.4): скачок ≤ 10 с, длительность ≥ 20 с, уровень по оснащению РМ.
   В режиме `Испытание` обе оценки всегда включены.

1b. **Момент оценки `tр`** (п. 4.2.5 / 4.2.9): среди квазиустановившихся по частоте точек (`|f − fср| ≤ 10 мГц` на ±15 с) после 15-й секунды выбирается худшая по дефициту первичной мощности. Если таких точек нет — конец контрольного интервала `X5`.

2. **Количественный критерий** в точке `tр` (п. 4.2.1–4.2.3 МУ); контрольный интервал `X5` сохраняется справочно (`Pтреб(Tинт)` / `Pфакт(Tинт)`):
   - `P0` и `Pтек` — текущие значения или средние за окно `X12` (п. 4.2.6);
   - `dF` = максимальное по модулю отклонение от `fном`;
   - `dFr` = отклонение за зоной нечувствительности;
   - `Pтреб_исх = -100/S · Pном/fном · Kд(t) · dFr`;
   - применяется **капинг по Pmax/Pmin**: `Pтреб = clip(Pтреб_исх, -max(0, P0-Pmin), max(0, Pmax-P0))`. Если произошло ограничение — статус становится `Ограничен Pmax/Pmin`;
   - `Pфакт = Pтек − P0`;
   - проверяется знак и уровень `|Pфакт|/|Pтреб|` с допуском `X6`.
   - Если `Колич. % > 100 + X6` — в `Summary` ставится метка `Перерегулирование`.
   - **Амплитуда** `= 100·|Pтреб_исх|/Pном` (по исходному, неограниченному значению — чтобы корректно характеризовать масштаб возмущения) и метка `Слабое / Норма / Избыточное`.

2a. **Реакция регулятора частоты вращения через 15 с** (п. 4.2.11 МУ):
   - `dP15 = P(tвых + 15 с) − P0`, где `tвых` — момент выхода частоты за `fнч` (по текущим значениям);
   - реакция есть, если `dP15` направлен против отклонения частоты и `|dP15| ≥ X11 % Pном` → статус `ОК`;
   - при **снижении** частоты отсутствие реакции на загрузку допустимо только при отсутствии запаса на открытие РК (`Резерв '+' < порога` по `Pmax`) → статус `Н/П`;
   - при **повышении** частоты реакция на разгрузку обязательна всегда; её отсутствие → `Нарушение` (фиксируется как несоответствие по величине первичной мощности в первые 15 с) и запись `WARN` в `Log`.

2b. **Дефицит первичной мощности по точкам окна** (п. 4.2.14.1 МУ, метод допустимых границ):
   - для каждой точки количественного окна, начиная с 15-й секунды, где частота вне `fнч`: `граница = |clip(Pтреб(t))| − 1 % Pном`, где `Pтреб(t)` считается по `Kд(t)` и текущему `dFr(t)`;
   - `дефицит = max(0, граница − dP(t)·sign)`; в `Summary` выводятся максимальный дефицит в `% Pном` и суммарная длительность дефицита, с (как замечание, оранжевым).

3. **Качественный критерий** (если `K=1`) — цели **масштабируются к статическому `Pтреб`** (`Kд = 1`, ограниченному резервом), поэтому критерий одинаково работает и при контрольных испытаниях (ступень 10 % `Pном` → `Pтреб = Pном·dp10%/100`), и при мониторинге реальных событий любой амплитуды; ступень считается достигнутой с допуском 1 % Pном (п. 4.2.7):
   - к моменту `t5` отработано не менее `dP5/dP10 · |Pтреб|` (по умолчанию 5/10 = 50 % `Pтреб` — соответствует `Kд(15 с) = 0.5` для ТЭС);
   - к моменту `t10` отработан полный `Pтреб` (с тем же знаком, возможны перерегулирования). Если к `t10` частота уже вернулась в зону нечувствительности (или `Pтреб(t)` снизился), ступень засчитывается при отсутствии дефицита относительно текущего `Pтреб(t)`;
   - «установившееся» значение мощности (среднее за `X10` последних секунд качественного окна) сравнивается со **средним `Pтреб(t)` в том же окне** (с учетом `Kд(t)`), допуск `Уст_допуск % Pном` — только если `R=1`.
     - Если к концу окна частота восстановилась, `Pтреб_ср ≈ 0` — генератор тоже должен вернуться к `P0`.
     - Если частота всё ещё отклонена, генератор должен держать соответствующий `Pтреб`.

4. **Характер переходного процесса** по траектории `ΔP(t)` на `[Старт ; Старт + t10]`:
   - считаются значимые экстремумы (> 5 % амплитуды);
   - 0–1 экстремумов → `Монотонный`;
   - 2–3 экстремумов с убывающими амплитудами → `Апериодический`;
   - ≥ 4 экстремумов или не убывающие амплитуды → `Колебательный`.

4a. **Колебания** (п. 4.2.14.4): более 5 периодов подряд с амплитудой > 1 % Pном, не связанные с колебаниями частоты (±3 с, размах f > 10 мГц) — нарушение.

4b. **Тип реакции** по п. 4.4.1 (1 адекватная … 8 телеизмерение). Для оборудования с РМ отсутствие «адекватной» — нарушение п. 4.4.4; без РМ фиксируется факт (п. 4.4.3: нарушение при ≥ 3 фактах за год — вручную).

4c. **Качество телеизмерений**: пропуски, более 11 одинаковых значений подряд, скачки > 20 % Pном.

4d. **h(15 с)** — идентификация переходной функции (Приложение, п. 6.2), справочно.

5. **Листы на генератор**:
   - `<Ст>_<Ген>` — параметры + временной ряд + вспомогательные колонки для маркеров;
   - `<Ст>_<Ген>_Граф` — отдельный лист с двумя графиками:
     - верхний: относительные ряды (`dP`);
     - нижний: абсолютные ряды (`P, МВт`) + `Частота, Гц` на вторичной оси.
     В блоке **Вывод** дополнительно показывается фактический `Kд` и примененный профиль `Kд(t)`.

Для каждой станции, у которой хотя бы у одного генератора `Q=1`:

- строится общий суммарный лист `<Ст>_Сумма` (данные) + `<Ст>_Сумма_Граф` (график);
- дополнительно по каждому уникальному значению колонки `Паропровод` строятся подгрупповые листы:
  - `<Ст>_Сумма_<Паропровод>` + `<Ст>_Сумма_<Паропровод>_Граф`;
- в сумму включаются только генераторы с мгновенной мощностью выше `X7` (п. 4.2.10 МУ: «включённое в работу и готовое к участию в ОПРЧ оборудование»); `Pном_сум`, `Pmax_сум`, `Pmin_сум` считаются по генераторам, бывшим в работе на момент старта;
- **`Pmax_сум` / `Pmin_сум`** считаются как сумма `Pmax` / `Pmin` включённых в работу генераторов. Располагаемый резерв и капинг `Pтреб_сум` работают как для отдельного генератора; на графике добавлены уровни `ΔPmax_сум` и `ΔPmin_сум`;
- по сумме вычисляются **количественный статус**, **реакция через 15 с** (п. 4.2.11/4.4.2) и **дефицит по точкам** — так же, как для генератора;
- формируется **вердикт по сумме** (лист `<Ст>_Сумма`, блок `G1:H6`; лист `<Ст>_Сумма_Граф`, строки 3–6; строка `СУММА` в `Summary`):
  - для **неблочной** части: `ОК по сумме … По п. 4.2.10 МУ индивидуальная оценка генераторов не требуется` / `НАРУШЕНИЕ … требуется индивидуальная оценка`;
  - для **блочной** станции сумма считается справочно; нормативная оценка — по каждому генератору;
- в столбец `Вывод` каждого генератора станции дописывается пометка `Станция в целом: ОК …` / `Станция в целом: не соответствует …`.

После расчёта формируется лист **`Протокол`** (текстовый протокол оценки по п. 4.4) и при необходимости PDF (`ExportOPRCHReport`).

## 6. Лист `Log`

При запуске автоматически формируется лист `Log` с предупреждениями и служебными сообщениями:

- разрывы по времени в `RawData` > 5 с;
- значения `S`, `fнч` вне типичных диапазонов;
- `WARN п. 4.2.11: Отсутствует реакция РЧВ …` — нет реакции регулятора частоты вращения через 15 с;
- `INFO Kд(t) <тип>` — фактические `Kд(15 с)` и `Kд(колич. интервал)` по каждому профилю;
- `INFO <Ст> (сумма)` — вердикт по сумме станции;
- `t10 < t5`;
- частично заполненная колонка `Паропровод` в рамках станции;
- `Pmax < Pmin`, `Pmax > 1.3·Pном`, `Pmin < 0`;
- резерв в требуемую сторону `< 5 % Pном` (возможное ограничение по диапазону);
- `INFO` о случаях капинга `Pтреб` по `Pmax` / `Pmin` с указанием исходного и применённого значений;
- другие замечания.

Если замечаний нет, в листе остаётся строка `INFO — Замечаний не обнаружено`.

## 7. Листы по генераторам и станциям

Листы по генераторам:
- `<Ст>_<Ген>` — параметры (включая `Pуст_сред`, `Характер`, `Экстремумов`, `Амплитуда`) и таблица временного ряда с вспомогательными колонками;
- `<Ст>_<Ген>_Граф` — график + блок **Вывод**.

Листы суммарные:
- `<Ст>_Сумма` + `<Ст>_Сумма_Граф`;
- `<Ст>_Сумма_<Паропровод>` + `<Ст>_Сумма_<Паропровод>_Граф` — если в `Config` заполнена колонка `Паропровод`.

## 8. Типовые ошибки и замечания

- `Не найдена колонка мощности/частоты ...` — проверьте `Config` (C/D) и заголовки в `RawData`.
- `Пропущен: не заполнены обязательные параметры` — не заданы `Pном`, `S` или `fнч`.
- `Для типа '…' не задан профиль Kд(t) в Config (AA:AI)` — имя типа в колонке `E` не совпадает с именем профиля в `AA` (сравнение точное, без учёта регистра).
- `Нет первичного отклика; проверьте генератор/датчик` — в `Summary` появляется, если `P0 ≈ 0` и `Pфакт ≈ 0` (генератор не в работе или отсутствует сигнал).
- `Слабое возмущение (< 3 %Pном)` / `Избыточное (> 10 %Pном)` — дополнительные пометки в `Примечание`: событие за пределами типичного нормативного диапазона 3–10 % Pном.

## 9. Рекомендуемый порядок работы

1. Выгрузите все сигналы в `RawData` и заполните `Config`.
2. При необходимости нажмите **Применить пресеты типов** — макрос заполнит пустые нормативные параметры по типу оборудования.
3. Нажмите **Запустить мониторинг ОПРЧ**.
4. Проверьте `Log` — если есть `WARN`, уточните конфигурацию.
5. Проанализируйте `Summary`: по цветам легко видно проблемные генераторы.
6. По каждому проблемному генератору откройте `<Ст>_<Ген>_Граф` — блок **Вывод** содержит краткую сводку, график подсвечивает `t5`, `t10` и момент выхода за `fнч`.
7. Откройте лист `Протокол` — текстовая сводка по п. 4.4; при необходимости нажмите **Экспорт отчёта в PDF**.
8. Для повторного запуска с другими параметрами нажмите **Очистить результаты** и затем снова **Запустить мониторинг ОПРЧ**.
